# State Fitted Sequential Action Value v1.7 — pre-registration

## Status

Pre-registered after v1.6 failed and before implementing or viewing any v1.7
trading result.

Use only the already-seen January-March 2026 development panels. Do not access a
fresh validation month.

This branch replaces hand-written action labels with explicit fitted action
values and backward induction.

## Frozen information and geometry

Use exactly the v1.3-v1.6 causal feature set:

- existing point-in-time price/volume/breadth/sequence state;
- exact 8 lagged FINRA short-volume features;
- exact 13 prior-8-K features;
- exact 8 publication-safe FINRA short-interest features.

Geometry is unchanged:

- BUY: enter and hold exactly 10 minutes;
- WAIT: advance exactly 5 minutes;
- SKIP: terminate with zero return;
- checkpoints at offsets 0, +5, +10 minutes from the first eligible state;
- at most one attempted BUY per ticker-day;
- missing required checkpoint after WAIT terminates with zero return.

No direct-EV gate, class threshold, feature search, or fresh month.

## Train-only backward partitions

For each leave-one-month-out fold, sort all training trading days
chronologically and split them into three non-overlapping contiguous partitions
as evenly as possible:

- partition A: earliest third;
- partition B: middle third;
- partition C: latest third.

No row may move partitions because of its outcome.

These partitions are used to prevent a WAIT target from being generated by a
future policy fitted on the same observations.

## Stage +10 model

Using partition A only:

- fit Q10_BUY(x) to realized 10-minute base-net return;
- Q10_SKIP is fixed at 0;
- executable +10 action is BUY iff predicted Q10_BUY > 0, otherwise SKIP.

The fitted +10 policy is then frozen for construction of downstream targets.

## Stage +5 models

Apply the frozen +10 policy to partition B's exact +10 checkpoints.

For every partition-B +5 checkpoint:

- Q5_BUY target = realized 10-minute base-net return from +5;
- Q5_WAIT target = realized return produced by the frozen +10 policy at the
  exact +10 checkpoint;
- if the exact +10 checkpoint is unavailable, Q5_WAIT target = 0;
- Q5_SKIP is fixed at 0.

Fit separate Q5_BUY and Q5_WAIT regressors using partition B only.

The executable +5 action is argmax(predicted Q5_BUY,
predicted Q5_WAIT, 0), with deterministic tie order SKIP, WAIT, BUY only for
exact numerical ties.

Freeze this +5 policy.

## Stage 0 models

Apply the frozen +5 policy, and when necessary the already frozen +10 policy, to
partition C.

For every partition-C initial checkpoint:

- Q0_BUY target = realized 10-minute base-net return from the initial state;
- Q0_WAIT target = realized return produced by the frozen downstream policy
  beginning at the exact +5 checkpoint;
- if +5 is unavailable, Q0_WAIT target = 0;
- Q0_SKIP is fixed at 0.

Fit separate Q0_BUY and Q0_WAIT regressors using partition C only.

## Regressors

All fitted Q regressors use identical fixed settings:

- HistGradientBoostingRegressor;
- loss="squared_error";
- learning_rate=0.05;
- max_iter=160;
- max_leaf_nodes=15;
- min_samples_leaf=75;
- l2_regularization=2.0;
- deterministic stage-specific random seed;
- target winsorization at the 0.5th/99.5th percentiles of that model's own
  training target;
- no affine calibration and no outcome-selected threshold.

The smaller leaf size versus earlier state-wide models is fixed before outcome
inspection because each stage contains only one row per ticker-day.

## Executable policy

For a held-out ticker-day:

1. at offset 0, choose the largest of predicted Q0_BUY, Q0_WAIT, and 0;
2. BUY attempts the 10-minute trade;
3. SKIP terminates;
4. WAIT advances to exact +5;
5. at +5 choose the largest of predicted Q5_BUY, Q5_WAIT, and 0;
6. WAIT advances to exact +10;
7. at +10 BUY iff predicted Q10_BUY > 0, else SKIP;
8. any missing required checkpoint after WAIT terminates with SKIP;
9. a BUY decision consumes the attempt even if unfillable.

No realized label is consulted in action selection.

## Comparators and diagnostics

Primary comparator: earliest_eligible_10m_cap1.

Report by month:

- trades, days, gross/base/stress mean;
- day-balanced mean, median, p05, positive rate, severe-loss rate, worst day;
- action path counts at 0/+5/+10;
- common-episode return delta versus earliest eligible;
- holdout Spearman of Q0_BUY prediction vs realized initial BUY return;
- holdout Spearman of Q0_WAIT prediction vs realized return of the frozen
  downstream policy starting at +5;
- coverage for all frozen external families;
- pooled trading-day-cluster bootstrap.

The historical v1.5/v1.6 branches may be shown only as diagnostics.

## Promotion rule

The branch passes development only if ALL conditions hold:

1. at least 15 executed trades in every month;
2. arithmetic base-net mean > 0 in every month;
3. day-balanced base-net mean > 0 in every month;
4. day-balanced base-net mean strictly above earliest_eligible_10m_cap1 in every
   month;
5. base p05 and stress-net mean are not worse than the comparator in any month;
6. both Q0_BUY and Q0_WAIT holdout Spearman are > 0 in every month;
7. short-volume latest-prior coverage >=90%, publication-safe short-interest
   latest coverage >=90%, and 8-K query completion =100% in every month;
8. pooled trading-day-cluster bootstrap 95% lower bound > 0.

If all eight pass, freeze this exact branch and pre-register one unseen
validation month before accessing it.

If the branch fails, do not tune partition fractions, Q thresholds, timing
geometry, winsorization, model capacity, or features on January-March. The next
research decision must use the failure diagnostics to decide whether the
remaining bottleneck is execution cost or state information rather than
repeatedly rewriting the policy.

No fresh validation month is consumed here.
